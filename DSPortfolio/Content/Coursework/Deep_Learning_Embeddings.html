Overview¶

This notebook builds a deep learning sentiment classifier using the Universal Sentence Encoder (USE) from TensorFlow Hub, applied to the same hotel reviews dataset used in Week 9. The target label is Is_Response — happy or not happy — label encoded as 0 and 1.

The architecture follows the pattern Sarkar (2019) establishes in Chapter 10: USE encodes each review into a fixed 512-dimensional embedding vector, then a dense Keras network classifies those vectors. The key difference from Week 9's TF-IDF + Logistic Regression approach is where the feature representation comes from. TF-IDF counted words. USE encodes meaning — two sentences using completely different words can land close together in the 512-dimensional space if they express the same idea.

TF 2.0 Compatibility¶

As the assignment notes, TF 2.0 introduced breaking changes. This notebook uses tensorflow.compat.v1 conventions where needed and sets TF_CPP_MIN_LOG_LEVEL=3 to suppress the verbose hardware warnings that TF 2.x produces by default.

TOTAL_STEPS and STEP_SIZE¶

Following the assignment guidance: TOTAL_STEPS = 100, STEP_SIZE = 10, giving 10 training epochs. The assignment explicitly notes that higher values (the author's 1500/100) would take many hours on a standard machine. The model still produces meaningful results at these settings — accuracy and loss trajectories are clearly visible across 10 epochs.

Data Split¶

The same three-way split from Week 9 applies here: 70% train, 15% validation, 15% test, stratified by class. USE receives the raw, uncleaned text — punctuation, capitalization, and sentence structure are all part of what USE was trained to encode. Cleaning would strip signals the encoder already knows how to use.

Step 4: Load the Universal Sentence Encoder¶

USE version 4 is loaded from TensorFlow Hub. The first load downloads the model (~1GB) and caches it locally — subsequent runs are faster. The encoder takes any string input and returns a 512-dimensional vector regardless of sentence length.

This is the transfer learning step. USE was pre-trained on a large corpus covering web pages, Wikipedia, forums, and question-answer pairs. It already knows that "sleep deprivation" and "poor sleep" are semantically similar before this notebook ever runs a single training step. The dense layers on top learn only how to map those 512-dimensional representations onto the hotel sentiment task — which is a much smaller learning problem than starting from scratch.

Encoding is batched in groups of 64 to manage memory. The np.vectorize approach the author uses in the text is skipped here per the assignment note — direct batching is more reliable and avoids the shape issues np.vectorize introduces with tensor outputs.

import time

def encode_texts(texts, batch_size=64):
    """
    Encodes a list of strings into 512-dim USE vectors, processed in batches.
    Batching avoids memory issues on large inputs.
    Returns a single numpy array of shape (n_samples, 512).
    """
    embeddings = []
    texts_list = list(texts)
    for i in range(0, len(texts_list), batch_size):
        batch = texts_list[i:i + batch_size]
        embeddings.append(embed(batch).numpy())
    return np.vstack(embeddings)

Step 5: Build the Keras Classification Model¶

The network sits on top of the USE embeddings. The input is always 512-dimensional — one number per USE dimension. Two dense hidden layers follow, each with Dropout applied.

Dropout randomly disables a fraction of neurons during each training step. It forces the remaining neurons to learn redundant representations — which prevents the model from memorizing the training data and improves generalization. The output layer uses a sigmoid activation, which maps the final value to a probability between 0 and 1: above 0.5 predicts not happy, below predicts happy.

Binary crossentropy is the loss function for binary classification — it measures how far the predicted probability is from the true label. Adam handles the gradient-based weight updates, adapting the learning rate automatically per parameter.

In [6]:
tf.random.set_seed(42)

model = tf.keras.Sequential([
    # Input: 512-dim USE embedding
    tf.keras.layers.InputLayer(shape=(512,)),

    # Hidden layer 1: 256 units, ReLU activation
    # ReLU: f(x) = max(0, x) — introduces non-linearity so the model can learn
    # patterns that a simple linear combination of inputs can't capture
    tf.keras.layers.Dense(256, activation='relu'),
    tf.keras.layers.Dropout(0.3),   # drop 30% of neurons per step during training

    # Hidden layer 2: 128 units, ReLU
    tf.keras.layers.Dense(128, activation='relu'),
    tf.keras.layers.Dropout(0.3),

    # Output: single sigmoid unit — probability of 'not happy' (label=1)
    tf.keras.layers.Dense(1, activation='sigmoid')
])

model.compile(
    optimizer=tf.keras.optimizers.Adam(learning_rate=0.001),
    loss='binary_crossentropy',
    metrics=['accuracy']
)

model.summary()

Step 6: Train the Model¶

Following the assignment parameters: TOTAL_STEPS = 100, STEP_SIZE = 10. Each epoch covers the full training set once, processing reviews in mini-batches of 32. The validation set is checked at the end of every epoch — this is how the training curves in the next section are produced.

Each epoch is one complete pass through the training data. Each pass updates the weights via backpropagation — the loss computed at the output travels backward through the network, adjusting each weight slightly in the direction that would have lowered it. Ten passes give the optimizer ten chances to refine those adjustments and move the loss toward its minimum.

Step 7: Training History — Loss and Accuracy Curves¶

The training history shows how loss and accuracy evolved across all 10 epochs. The gap between train and validation curves reveals how the model generalizes. A validation loss that tracks below the training loss early on — which happens here — is a sign that the USE embeddings are doing a lot of the heavy lifting before the dense layers even learn much. The 512-dimensional representations are already semantically organized, so the classifier converges quickly.

Reading the Training Curves¶

Epoch 1 is the most informative. Train loss starts high (~0.44) while validation loss is already low (~0.10). That gap reflects USE doing the semantic work before the dense layers have learned anything — the 512-dimensional embeddings already separate happy and unhappy reviews meaningfully, and the classifier picks that up immediately on the validation set.

By Epoch 2, both curves converge near zero and stay there. The model has found the classification boundary and the remaining epochs are refinements — each backpropagation pass nudges the weights slightly, but the direction barely changes because the gradient is already small.

On a real-world corpus — PubMed abstracts, Reddit threads, qualitative survey responses — this curve would look very different. The language would be more varied, the sentiment signals more ambiguous, and the loss would take many more epochs to descend. The hotel review dataset's directness makes the learning problem easier than the evaluation numbers suggest.

Step 9: Week 9 vs. Week 10 — Model Comparison¶

Both the Week 9 TF-IDF + Logistic Regression model and this USE deep learning model achieved 100% test accuracy on this dataset. The comparison is still worth making because the path to that accuracy is completely different.

Dimension TF-IDF + Logistic Regression USE + Dense Network
Feature source Word frequency counts (sparse) Pre-trained sentence embeddings (dense 512-dim)
Text cleaning Required (stopwords, lemmatization) None — USE handles raw text
Training data needed Labeled examples only Pre-trained + labeled examples
Vocabulary Fixed to training corpus Universal — handles unseen words
Handles paraphrase? Rarely — word overlap dependent Yes — semantic space captures meaning
Test accuracy 100% 100%

The critical distinction is vocabulary handling. TF-IDF assigns a weight of zero to any word it didn't see in training — if a review uses "dreadful" and the model was trained on reviews using "terrible," TF-IDF misses the connection. USE encodes both words into similar regions of the 512-dimensional space because it learned from general language at scale. That generalization matters enormously on noisier, more varied corpora.

For the screen-time NER project downstream, USE embeddings could encode PubMed abstracts and Reddit posts into the same vector space — enabling semantic similarity across very different writing registers. That's exactly the cross-source comparison Milestone 1 identified as the project's end goal.

Observations and Interpretation¶

The USE model converges faster than any other approach tried across Weeks 9 and 10. By Epoch 2, both train and validation accuracy are at 1.00 and loss is effectively at zero. That speed is a direct consequence of transfer learning — the 512-dimensional embeddings arrived already organized by meaning, so the dense classifier only needed a handful of gradient steps to learn where the boundary between happy and not happy sits in that space.

The 100% test accuracy, like in Week 9, reflects the relative simplicity of the synthetic hotel dataset. The reviews use direct, unambiguous sentiment language — "absolutely wonderful," "terrible experience" — that any semantic encoder handles with ease. On a corpus with more nuance (sarcasm, qualified academic language, mixed-sentiment reviews), the advantage of USE over TF-IDF would show up more clearly in the evaluation numbers. USE's vocabulary generalization and paraphrase handling would pull ahead on cases where exact word overlap is low but semantic meaning is shared.

The most practically useful observation is the one the loss curve shows in Epoch 1: the validation loss was already lower than the training loss before the model had learned anything. That pattern tells you the pre-trained encoder is doing the real work. The dense layers on top are a relatively thin classifier sitting on a very powerful semantic foundation.
